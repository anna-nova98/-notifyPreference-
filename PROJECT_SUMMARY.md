# Notification Preferences Service - Краткое описание

## 🎯 Цель проекта
Сервис управления предпочтениями уведомлений, который служит единым источником правды для продуктовых модулей, отправляющих пользователям уведомления по нескольким каналам.

## 📋 Основные функции

### 1. Управление настройками
- **Дефолтные настройки** для новых пользователей
- **Индивидуальные настройки** по типам уведомлений и каналам
- **Глобальные политики** по регионам
- **Quiet hours** с учётом таймзоны

### 2. Проверка уведомлений
- Проверка возможности отправки уведомления
- Учёт всех правил и ограничений
- Подробное объяснение причин отказа

### 3. API
- REST API с JSON форматом
- Валидация всех входных данных
- Идемпотентность операций

## 🏗️ Технологии

- **Backend**: TypeScript, Node.js, Express
- **База данных**: PostgreSQL, TypeORM
- **Тестирование**: Jest, Supertest
- **Контейнеризация**: Docker, Docker Compose
- **Валидация**: Zod
- **Даты/время**: date-fns, date-fns-tz

## 🚀 Быстрый запуск

```bash
# 1. Клонировать репозиторий
git clone <repository-url>
cd notification-preferences-service

# 2. Запустить через Docker Compose
docker-compose up -d

# 3. Проверить работу
curl http://localhost:3000/api/v1/health
```

## 🔧 API Endpoints

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/v1/users/:id/preferences` | Получить настройки пользователя |
| POST | `/api/v1/users/:id/preferences` | Обновить настройки пользователя |
| POST | `/api/v1/evaluate` | Проверить возможность отправки |
| GET | `/api/v1/policies` | Получить глобальные политики |
| POST | `/api/v1/policies` | Создать/обновить политику |
| GET | `/api/v1/health` | Проверка здоровья сервиса |
