# Notification Preferences Service - Информация для проверяющего

## 🎯 Выполненные требования тестового задания

### 1. Хранение настроек ✅
- **Дефолтные предпочтения** для новых пользователей
- **Индивидуальные настройки** пользователя по типам уведомлений и каналам
- **Глобальные политики** (запрет определённого типа уведомлений по региону)

### 2. API ✅
- `GET /api/v1/users/:id/preferences` - получение текущих предпочтений пользователя
- `POST /api/v1/users/:id/preferences` - изменение предпочтений пользователя
- `POST /api/v1/evaluate` - проверка возможности отправки уведомления

### 3. Бизнес-правила ✅
- Учёт дефолтных настроек
- Учёт индивидуальных настроек пользователя
- Учёт глобальных политик по типу/каналу/региону
- Quiet hours с учётом таймзоны
- Идемпотентность операций изменения настроек

### 4. Технические требования ✅
- **TypeScript** по всему backend-коду
- **Читаемая структура проекта** с разделением на слои
- **Аккуратные доменные типы** для notificationType, channel, region
- **Работа с датами и таймзонами** через date-fns/date-fns-tz
- **Тесты** для ключевого поведения

## 🧪 Тестовые сценарии (все покрыты unit-тестами)

1. **Новый пользователь и дефолты** - `should create default preferences for new user`
2. **Изменение настроек пользователем** - `should update user preferences`
3. **Quiet hours** - `should deny notification during quiet hours`
4. **Глобальные политики** - `should deny notification by global policy`
5. **Идемпотентность** - проверяется в тестах обновления настроек
6. **Валидация** - `should throw error for invalid hours`

## 🏗️ Архитектура

Проект следует принципам **чистой архитектуры**:

```
src/
├── domain/           # Доменный слой (не зависит от фреймворков)
│   ├── types.ts     # Доменные типы и enum
│   ├── entities.ts  # Сущности TypeORM
│   ├── services.ts  # Бизнес-логика
│   └── repositories.ts # Интерфейсы репозиториев
├── infrastructure/   # Инфраструктурный слой
│   └── repositories.ts # Реализации репозиториев (TypeORM)
├── api/             # Слой представления
│   ├── controllers.ts # Контроллеры Express
│   └── routes.ts    # Роуты
└── config/          # Конфигурация
    └── database.ts  # Конфигурация БД
```

## 🔧 Ключевые решения

### 1. Типизация
- Использованы TypeScript `enum` для `NotificationType`, `Channel`, `Region`
- Строгая типизация всех DTO и доменных объектов
- Валидация входных данных с помощью **Zod**

### 2. Работа с временем
- Использование **IANA timezone** для quiet hours
- Корректная обработка интервалов, переходящих через полночь
- Конвертация времени в таймзону пользователя при проверке quiet hours

### 3. Идемпотентность
- Операции обновления настроек используют `upsert` (create or update)
- Повторное применение одной и той же команды не меняет состояние

### 4. Масштабируемость
- Интерфейсы для всех репозиториев
- Легко заменить реализацию хранилища (TypeORM → другой ORM)
- Чистое разделение ответственности
